# 費率排程與繼承

此專案是使用瀏覽器 localStorage 的示範平台，沒有支付回呼或後端結算服務。

## 設定與生效

- 支付工具：逐項新增；初始費率立即生效。列表逐筆顯示費率版本，包含幣別、手續費開始時間 (GMT+8) 與狀態；點擊支付工具名稱開啟編輯視窗，以相同欄位及新的開始時間儲存費率版本。待生效版本可直接修改，已生效版本另存新版本。新增與編輯視窗不顯示費率歷程按鈕，歷史版本仍保留於資料中。
- 搜尋：第三方金流平台預設全部，可選藍新金流、Line Pay、街口支付、台灣行動支付，與關鍵字共同篩選；清除會重設兩者。此選單目前為示範設定，待 IT 改為從資料庫提供。
- 商店：在商店列表按「費率設定」，所有工具整組儲存，各工具選擇繼承全站或自訂。
- 專案：在專案列表按「費率設定」，所有工具整組儲存，各工具選擇繼承商店或自訂。
- 繼承保持連動，不複製上層數值。新增工具會自動出現在所有設定中；舊的整組版本沒有該工具時視為繼承。
- 時間欄位為台北時間 UTC+8，儲存為 UTC。付款成功時間等於生效時間即套用新版本。
- 待生效版本可修改、取消。修訂保留原版本與操作者；已生效的版本不可回溯修改。
- 商店、專案的自訂費率沿用工具既定計價單位；已建立工具不可更改單位。
- 管理權限沿用目前系統規則，僅系統管理員可設定費率。

## 交易費率快照

交易付款成功時，以確定的專案 ID、支付工具 ID、實際付款成功時間記錄費率：

```js
const snapshot = TransactionFees.record({
  id: 'ORDER-20261101-001',
  projectId: 'A',
  toolId: 'credit-card',
  paidAt: '2026-11-01T00:00:00+08:00',
  amount: '10000.00',
});
// snapshot contains fee, unit, source, sourceId, versionId, feeAmount and paidAt.
```

重複記錄相同交易會回傳原快照；交易參數不符時拒絕修改。計費使用十進位整數運算，延續示範平台以新台幣整元四捨五入；固定元費用同樣四捨五入，不另設最低費。

訂單明細和對帳單優先使用已記錄快照。既有示範訂單缺少可核對的專案 ID，部分支付時間也不完整，因此保留原本的示範費用，不依名稱猜測專案或回溯重算。實際支付串接時，必須由可信任的後端付款成功流程呼叫相同的費率解析與快照邏輯，並以資料庫交易與唯一訂單索引實現原子性；本示範的 localStorage 不能作為正式金流帳務儲存。

## 驗證

`npm test` 包含生效時間邊界、逐層繼承、整組切換、取消與修訂、動態新增工具、權限、歷史快照、資料遷移與十進位計費測試。

`npx playwright test` 包含費率排程、整組設定、儲存後重載、交易明細快照與既有介面流程。
