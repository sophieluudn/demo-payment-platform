# 三層費率、排程與交易快照

本專案是瀏覽器儲存的互動 demo，不含正式支付或排程服務。

## 解析與權限

有效專案自訂 → 有效商店自訂 → 有效全域設定。商店及專案預設繼承；`{mode:"inherit"}` 連動上層，不複製費率值。`{mode:"custom",fee:"2.5"}` 表示自訂。沒有有效自訂版本（未開始、已結束、停用或取消）則往上層解析。

商店費率按目標商店驗權，專案費率按目標專案驗權，全域費率需平台 fees 權限。交易檢視不代表費率管理。一般角色有相應功能及範圍即可設定，不再限系統管理員。

費率的新增與編輯沿用合併授權，設定入口與模型儲存均按目標層級驗權；缺少平台費率權限時明確提示權限不足，不能以專案費率權限修改全域設定。

支付工具名稱、第三方平台、代碼、幣別及備註使用平台 payments 權限，費率使用獨立 fees 權限。新增工具同時設定初始費率，需兩者。僅具基本資料編輯權時只修改基本資料，保留費率歷程。

列表顯示繼承／自訂、目前生效值及來源；版本視窗可切換繼承／自訂。工具啟用狀態保留既有設計：商店可獨立設定，專案自訂可覆寫；未覆寫的專案狀態繼承商店。

## 版本規則

各層級完整儲存當次各工具設定。後來新增的工具在未設定的下層版本繼續往上繼承。以台北時間輸入、UTC 儲存；開始含當下、結束不含當下。重疊期間選擇已啟用且開始時間最近的有效版本，空窗往上繼承。

待生效版本可修訂或取消；修訂保留舊版並建立替代版本。生效中鎖定費率及開始時間，只能修改結束時間與狀態；已結束唯讀。啟停與結束時間異動保留操作者、時間及前後值。停用後由仍在有效期間的上一版本接手，否則繼承上層。

## 快照與遷移

recordTransactionFee／TransactionFees.record 接收明確訂單 ID、專案 ID、工具 ID、付款成功時間及金額，按付款時間解析並鎖定費率來源、版本與費用。相同 ID 不重算，計費資料不同則拒絕。後續設定不改歷史快照；明細分開顯示預估費用及已鎖定快照，不會因讀取畫面替舊交易自動建立快照。

feeVersions、feeSnapshots 原樣保留。舊 fees 中可驗證目標及數值的 store:ID／project:ID 信用卡覆寫只匯入一次，其餘工具繼承。原值另存 legacyFeeOverrides；不明值不猜測套用，重複遷移不恢復已取消版本。逐專案授權不轉成整店。

npm test 驗證三層繼承、時間邊界、修訂、取消、停用回退、範圍權限、遷移及快照；npm run test:browser 驗證實際費率視窗、繼承切換與授權互動。

正式服務須由 IT 在服務端驗權、驗證支付回呼、原子鎖定快照、保存稽核及處理並行更新。
